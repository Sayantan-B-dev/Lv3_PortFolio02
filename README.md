# Sayantan Bharati — 3D Portfolio

A walkable, browser-based 3D portfolio for Sayantan Bharati, a full-stack developer working with MERN, Next.js, Python and WebGL. Every room is a cylinder with a single door, its own space backdrop, and content that can be read or opened in place.

The project is frontend-only, statically prerenderable, and built with Next.js 16 (App Router, TypeScript, Tailwind CSS), Three.js, React Three Fiber, Drei and Vitest.

## The experience

The visitor starts in a Home room with seven doors: one that recentres the view and six that lead to the portfolio. Every themed room has one door that asks whether to go home or continue to the next room, so the loop is explicit:

```text
Home -> Architect -> Gallery -> Core -> Journey -> Playground -> Gateway -> Home
```

| Room | Purpose | Content |
| --- | --- | --- |
| `home` | Hub | Seven doors, wandering cats, one note |
| `architect` | About and skills | Intro notes, focus, toolkit, looping clips |
| `gallery` | Projects | BlueEye, LnkZoo and Re-Docs plaques with live/source links |
| `core` | Technical range | MERN, Next.js, Python, databases and WebGL |
| `journey` | Background | Experience, education and six certificate frames |
| `playground` | Experiments | Floating cats, space cinema, looping clips, notes |
| `gateway` | Contact | Email, GitHub, LinkedIn, Fiverr and hiring notes |

Rooms are arranged on one cylinder. The door sits at angle `0` (the front wall), the title and content sit at `π` (the back wall), and the visitor spawns between the centre and the front door facing the content. Furniture positions and collision footprints live in `src/content/layout.ts`.

## Content and assets

Everything the visitor reads is in `src/content/`:

- `rooms.ts` — titles, copy, palettes, windows, doors, frames and notes for all seven rooms.
- `portfolio.ts` — profile facts, links, skills, projects, education, experience, certifications and hiring copy.
- `profile.ts` — `NEXT_PUBLIC_*` overrides with committed defaults.
- `config.ts` — site metadata and HUD strings.
- `layout.ts` — circular furniture placements shared by the rooms and player collision.

Assets are served from `public/`:

- `public/models/` — the shipped GLB models, including six space backdrops and the reduced `-low` exports.
- `public/images/frames/` — nine short looping clips used by the animated frames.
- `public/certificates/` — the eight certificate images.
- `public/profile/` — the profile photos.
- `public/wall-textures/` — the downscaled plaster wall.
- `public/assets/source/` — sources only; not part of the preload index and never referenced by the app.

`public/fetch_file_index.json` is generated by `npm run index` from `scripts/build-file-index.mjs`. It lists every preloaded file with its type, room scope (`shared` or a room id), quality tier, byte size and display name. Regenerate it after adding, removing or replacing a preloaded asset.

`public/music/` is scanned at build/start time; every audio file joins the root playlist in alphabetical order. While a track plays only the next two tracks are fetched. `public/sfx/` holds the interaction sounds. `public/vid/oiiaoiia.mp4` is streamed only after the playground cinema button is pressed.

## Loading

1. Render the server shell and the intro immediately.
2. Fetch the asset index once, then load the `shared` files and the landing room (`home`).
3. Report real bytes, completed assets, total assets and the current file.
4. Warm shaders and paint frames behind the intro.
5. Reveal the scene, then warm the other rooms in door order.
6. A door never starts a fetch: if the destination is still warming, the door waits with visible progress.

Slow connections and coarse pointers select the `low` tier, which swaps in the reduced model exports. Feature-detect in `getAssetTier()` rather than branching in each room.

## Local development

```bash
npm install
npm run dev
npm run test
npm run index
npm run lint
npm run build
```

The dev server runs at `http://localhost:3000`.

Optional identity overrides (all public, all safe to commit only as the example file):

```bash
NEXT_PUBLIC_PROFILE_NAME="Sayantan Bharati"
NEXT_PUBLIC_PROFILE_ROLE="Full Stack Developer"
```

No database, authentication, API routes, server actions or private secrets are used.

## Checks

- `npm run test` covers room navigation, door labels, content and asset paths, the preload index, profile stats, the PWA shell and the music playlist.
- Check the full door loop manually, including the Home door and the gateway wrap.
- Check the console on a cold load and after a room transition.
- Test a mobile-sized landscape viewport and a missing optional asset.
- `npm run build` is the final check for scene, routing or configuration changes.
